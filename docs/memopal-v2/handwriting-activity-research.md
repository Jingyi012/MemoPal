# 屏幕书写活动研究：描红、临写与无提示书写

研究日期：2026-10-27。对象：MemoPal 下一阶段的小学书写练习设计。本文是研究与方案建议，不是已实现功能、课程标准认定或自动评分承诺。

## 结论摘要

- 书写活动要区分**描红/跟随示范**、**临写/看范字后书写**与**无提示回忆书写**。三者给学生的线索不同，活动成功不能合并为一个“会写”指标。
- 一手教育来源强调规范字形、笔画笔顺、部件与结构、书写习惯，并要求按学段循序渐进；一项儿童记忆研究发现，描摹或缺少反馈会削弱重复书写对新字符回忆的优势。产品应把描红作为动作熟悉/示范练习，而把无提示书写及延后重试作为更强的学习证据。
- `react-native-svg` 与 `react-native-gesture-handler` 已在移动项目依赖中；Expo SDK 54 官方文档列出 SVG 支持 Android/iOS/Web。可以用本地矢量画布做低风险 MVP，无需先引入绘图库或下载整套字库数据。
- Hanzi Writer 的 JS 代码 MIT 许可不等于汉字轨迹数据也是 MIT。官方仓库说明数据源自 Make Me a Hanzi / Arphic 字体，数据采用 Arphic Public License（APL）。修改后的数据再分发涉及显著修改标注及向第三方以 APL 提供修改版本等义务。第一版建议不内嵌该数据；逐字人工审核并自制最小试点数据，或只链接官方在线资源并先审查其条款。
- 轨迹与模板接近只表示当前输入在某种提示和设备条件下接近参考，不足以证明能独立回忆、迁移到纸笔或长期掌握。自动反馈先限于可解释的练习过程提示，独立掌握判断需无提示、延时、跨题与教师核验的证据。

## 当前产品与代码基线

### 已核实事实

- [MemoPal 2.0 产品计划](product-redesign-plan.md)明确把小学多学科学习作为方向，并写明：手写需审核笔顺数据、画布及轨迹合同；描红完成不等于独立书写；第一版不承诺手写自动批改。手写属于后续媒体活动阶段。
- 当前移动端题型中已有 `photo-response`，答案是附件 ID，不是笔画序列。`PhotoResponseInput` 通过 `expo-image-picker` 选图并上传；教育实施记录说明图片经验证后存储为私有附件，正式作业经教师人工评分，待开放题评分完成前不发布结果。
- 已有公开练习播放器明确排除 `written-response`、`photo-response`、`voice-response`。所以照片作答不能直接塞进客观练习播放器，也不能被解释为可实时判分的画布。
- 移动端 `package.json` 已包含 Expo SDK `~54.0.33`、React Native `0.81.5`、`react-native-svg` `15.12.1`、`react-native-gesture-handler` `~2.28.0`、`expo-file-system` 与 `expo-image-picker`。当前仓库没有独立书写画布或轨迹答案合同。

### 实施含义（提案）

新画布应作为教育学习活动单独设计输入、保存/恢复、内容作者、答案与评分合同；复用现有认证附件上传仅适用于需教师看结果的**照片作品/人工评分**。初期将画布的练习完成状态与正式成绩、掌握度、复习调度分开，不映射到 `practice-attempts` 或既有客观题评分。

## 教学目标：三个提示水平

以下是设计词汇，不冒称某一国家或地区的课程等级。官方来源可支持“逐步形成书写动作与规范、依学段要求练习”，但没有给出 MemoPal 必须采用的固定三段式。

| 活动形态 | 学习者看到的线索 | 适合的近期目标 | 不能据此声称 |
| --- | --- | --- | --- |
| 描红/跟随动画 | 范字、轮廓或单笔轨迹，可能提示起笔/方向 | 认识笔画方向、尝试动作、降低初次练习负担 | 独立记住字形、会默写、能迁移到纸笔 |
| 临写/看范字后写 | 范字持续可见，但书写区为空 | 观察并再现整体部件与比例；从视觉范例中练习 | 无提示回忆，或脱离范例也能书写 |
| 无提示书写/听写 | 只给读音、意义、听到的词或情境等不暴露目标字形的线索；写完后才显示范字 | 提取字形、笔顺与结构；检查独立产出 | 长期保持或泛化到生字、纸笔，除非另外延时/迁移测量 |

**事实依据：** 教育部办公厅 2024-09-30 发布的通知，网页发布日期 2024-10-25，要求按不同学段认知和身心特点安排汉字书写教育，掌握笔画笔顺、偏旁部首和间架结构，逐步学会书写正楷，并提出书写质量、速度与激励性评价。它是政策指导，不是对某种 App 交互或自动评分的实验验证。[教育部通知](https://www.moe.gov.cn/srcsite/A18/s7066/202410/t20241022_1158740.html)

教育部 2013-01-18 发布的《中小学书法教育指导纲要》指出，小学低年级以铅笔正楷、基本笔画、常用偏旁和基本笔顺规则为内容，并借助习字格把握笔画和结构，要求规范、端正、整洁。[教育部指导纲要](https://hudong.moe.gov.cn/srcsite/A26/s8001/201301/t20130125_147389.html)

IES What Works Clearinghouse 的小学写作实践指南（2012 年 6 月发布，2018 年 10 月修订）将“使学生熟练掌握书写、拼写、造句、打字和文字处理”列为建议，适用年级为 1–6 年级、证据等级为中等。指南谈的是写作流畅度教学，不验证描红轨迹比较，也不支持单次屏幕练习作为熟练度判定。[IES 指南与日期/证据等级](https://ies.ed.gov/ncee/wwc/PracticeGuide/17/Published)

**研究证据边界：** Naka 1998 年研究了日本一、三、五年级儿童学习伪汉字与外文字母，报告书写比只看更利于回忆，但描摹或无反馈条件会削弱书写优势。研究材料不是常用汉字课堂课程，不能推出所有儿童、字种或数字触控都必然如此；它支持产品不要把“手指沿着范字走过”直接当作独立记忆。[PubMed 记录（1998-07）](https://pubmed.ncbi.nlm.nih.gov/9701971/)

Cherng、Liao、Chen 的 2018 年研究让 25 名小学低年级儿童在数位板书写 6 个新汉字，比较有/无笔顺教学并重复 40 次；若干轨迹、时间和速度指标出现练习及笔顺教学效应，部分指标到第 40 次仍未平台。样本小、任务限于新字数位板书写，研究不是商用评分器验证。[UC eScholarship 论文摘要（2018）](https://escholarship.org/uc/item/7xc1m022)

### 建议的反馈目标

1. **描红时反馈过程，不发掌握徽章。** 例如“从横线开始”“下一笔向下”，允许重播示范、撤销和清屏。描红环节若评价覆盖率，只称“完成这次描红”。
2. **临写后对照范字给具体可操作提示。** 可先采用老师预设/人工审核的笔画数、部件位置示范；提示避免笼统的“错了”或羞辱性表达。若算法不确定，允许跳过评判。
3. **无提示后再显示标准字形及笔顺回看。** 鼓励孩子先自行写，再比较；可记录“独立尝试后查看提示”与“在提示下完成”，但不要把一题结果升级为长期掌握。
4. **延后回想才作为更强证据。** 产品可在之后的小课中隔一段时间重新无提示呈现同字，必要时换成部件辨认或组字任务；这属于产品评估提案，间隔需试点，不宣称固定日程有科学最优性。
5. **教师反馈针对可教的书写目标。** 试点 rubric 可分别标注字形可辨、笔画笔顺、部件/空间结构、书写姿势/纸笔迁移；书写速度不宜用于低龄初学者的惩罚性排名。

## 汉字笔顺/字形数据和许可

### 一手来源核查

- 教育部发布的 GF 0023-2020《通用规范汉字笔顺规范》标明 2020-11-23 发布、2021-03-01 实施；该标准是规则/规范来源，不等于网页上任何可下载矢量文件都自动获准再分发。[标准 PDF](https://www.moe.gov.cn/jyb_sjzl/ziliao/A19/202103/W020210318300204215237.pdf)
- 台湾教育部「常用国字标准字体笔顺学习网」提供笔顺查询、动画、字体和教学素材下载，但该页面的版权标记本身没有逐个说明素材的商业再分发许可。本研究未核实可供 MemoPal 内嵌分发的明确开放许可，因此不作可商用结论。[教育部学习网资源页](https://stroke-order.learningweb.moe.edu.tw/resource.jsp?ID=1)
- `hanzi-writer` 的代码仓库说明库代码为 MIT，但另指向独立的 `hanzi-writer-data` 数据仓库。项目 `COPYING.md` 明确说其字形数据源自 Make Me a Hanzi 和 Arphic 字体，数据可按 Arphic Public License 分发/修改。[Hanzi Writer README](https://github.com/chanind/hanzi-writer)；[COPYING.md](https://github.com/chanind/hanzi-writer/blob/master/COPYING.md)；[独立数据仓库](https://github.com/chanind/hanzi-writer-data)
- 仓库里的 [ARPHICPL.TXT](https://github.com/chanind/hanzi-writer-data/blob/master/ARPHICPL.TXT) 许可文本规定：未修改字体文件可在保留未更改许可证副本的前提下复制/分发；修改版本需在每个修改文件中显著说明修改内容、时间等，并要求修改版本作为整体依 APL 向第三方“Freely Available”。许可还明确“Freely Available”不代表不得收费。应用可收费与修改数据集再分发义务是两回事。
- [Make Me a Hanzi 仓库](https://github.com/skishore/makemeahanzi) README 说明数据包括汉字笔画图形资料；其相关版权/许可说明是 Arphic Public License。不要将 Hanzi Writer 的 MIT 代码许可误标成全部数据 MIT，也不要仅因“open source”就忽略 APL 条件。
- [KanjiVG](https://github.com/KanjiVG/kanjivg) 标注 CC BY-SA 3.0，需要署名并对改编材料按相同许可分享；其项目是日文 Kanji 数据，字形标准与简繁中文教学目标未必一致，不作为 MemoPal 汉字 MVP 的直接数据源。

### 许可处理建议（提案，不是法律意见）

1. MVP 不打包全量第三方字库；以极少量教师审核过的试点汉字，自制 SVG/矢量笔画并保存来源记录、审核人和目标字体标准。独立绘制仍须由内容负责人确认不复制受保护的具体字帖素材。
2. 若决定采用 Hanzi Writer 数据，先由负责人审阅当前代码、数据、字体来源和 APL 原文；在应用/包中保留完整许可文本、逐文件/数据集的修改说明，准备按 APL 向第三方提供相应修改数据的方式，并评估实际分发是否可接受。不能只复制 JS 包或只放 MIT 文本。
3. 若只调用/链接教育部网站而不缓存和再分发素材，仍需检查网站使用条款与具体字体/下载资源的许可；页面有教育用途不代表当然可商用。
4. 把简体/繁体、地区字形、目标正楷字形、异体字及笔顺例外作为内容审核问题。教育部 2024 通知引用通用规范；2013 指导纲要也提示笔顺教学要按规范。禁止未经核验地以单一数据来源宣称“唯一正确”适用于所有地区或课程。

## Expo / React Native 画布方案与无障碍

### 项目可复用事实

- Expo SDK 54 官方 SVG 参考列有 Android、iOS、Web 支持，推荐版本 `react-native-svg` 15.12.1，并提供 `Svg`、`Path` 等矢量原语示例。[Expo SDK 54 SVG 文档](https://docs.expo.dev/versions/v54.0.0/sdk/svg/)（页面未列明确发布日期；本研究按 SDK 版本查看，访问于 2026-10-27。）
- Expo 手势教程说明 `react-native-gesture-handler` 使用平台原生触摸系统识别 tap、pan、rotation 等手势，并要求手势组件位于 `GestureHandlerRootView` 内。[Expo 手势教程](https://docs.expo.dev/tutorial/gestures/)（页面未核实发布日期，访问于 2026-10-27。）
- React Native 无障碍 API 支持通过 `accessible`、`accessibilityLabel`、角色、提示和动态区域向 VoiceOver/TalkBack 呈现操作与状态；官方文档同时说明平台差异存在。[React Native Accessibility](https://reactnative.dev/docs/accessibility)（页面未核实发布日期，访问于 2026-10-27。）
- W3C WCAG 2.2 2.5.1 指出路径型手势需有非路径替代，除非路径本身是必要功能；描画本身显然有书写目标，但同一学习目标应有替代参与方式。W3C 的网络标准不等同原生 App 合规判定，仍是有用的设计依据。[WCAG 2.2 Pointer Gestures](https://www.w3.org/WAI/WCAG22/Understanding/pointer-gestures.html)（WCAG 2.2 于 2023-10-05 成为 W3C Recommendation；网页含更新记录。）

### 最小实现建议

1. 一个固定比例的写字格容器，`react-native-svg` 绘出格线、范字提示轮廓和孩子当前轨迹；`react-native-gesture-handler` 的 pan 输入采集点序列。把坐标归一化到格子宽高，抵抗屏幕大小差异。每个学习阶段由内容配置控制展示模板/动画/隐藏提示，不把评分算法与渲染组件耦合。
2. 只支持单指书写、笔画清除/撤销、重播示范、下一题和退出；多点触控仅作为系统缩放/辅助技术，不绑定学习操作。笔触适当加粗并提供足够画布空间，支持屏幕方向变化、文字缩放周围指引和降低动态效果。
3. 为不能或不希望绘画的孩子提供等价学习目标替代：用大按钮选择笔画方向/笔顺、按顺序点选分解笔画、选出部件位置，或在正式开放题中提交纸上书写照片请教师看。读屏操作需将目标字、当前第几笔、动作提示、清屏/撤销等作为有标签控件和文本状态播报；不能要求读屏用户操作一整块无语义 SVG。
4. 替代模式不能声称孩子练了手部书写动作；应把能力证据标为“笔顺辨认/结构判断”。若学习目标就是实际书写动作，无法完成画布时可提供教师/家长协助的纸笔活动或照片提交，明确为人工反馈路径。
5. 第一轮只在客户端本地绘制，不自动上传原始轨迹，也不做云端比较/个人画像。若教师布置要求留存作品，复用已有受认证、私有的照片上传及人工评分工作流；上传失败要能重试，显示“待老师查看”，不做即时判对。不要将 `localUri`、未经授权的孩子作品或轨迹点写入普通日志/分析。
6. 若未来要同步可编辑轨迹，应另订有版本的答案 DTO、字形/笔画数据版本、幂等保存与删除/保留期限、文件/API 限制及老师端可视化，不把大体量 trace 当普通练习 attempt answer 字符串。

## 自动书写评价：能力边界与验证要求

### 不能由轨迹接近直接推断掌握

- 描红中的轨迹被模板引导，成功只说明在该提示条件下完成一次动作。它与遮住范字后的独立提取任务不同。
- 一张静态照片看不到书写时间、笔画顺序、抬笔/空中轨迹；一串屏幕点也不代表纸笔工具、姿势、握笔和书写压力相同。
- 模板重叠得分受参考字形、字体、容差、起止点归一化、绘制空间、手指/触控笔差异影响。相似度可能把可辨识但笔顺变体的写法判错，也可能让描摹“贴模板”被误报为会写。
- 2018 年 25 名儿童研究同时测量轨迹、速度、纸面时间、空中时间及速度变化；不同指标受笔顺指示影响不同，且多项仍随着重复练习变化。这说明评价目标需先定义、多个指标不可混为一个总分；研究本身没有验证产品级独立掌握判定。[Cherng et al. (2018)](https://escholarship.org/uc/item/7xc1m022)
- 1998 年儿童记忆研究发现描摹和无反馈会削弱所观察到的重复书写记忆优势。这不代表描红没有教学用途，而是提示不能把“完成描红”当作回忆证据。[Naka (1998)](https://pubmed.ncbi.nlm.nih.gov/9701971/)

### 未来评测若要做自动反馈，最低数据与实验条件

这部分是建议的验证设计，而非已有平台能力：

- **明确定义标签：** 至少分开可辨识度、笔画数量/完整性、笔顺、部件/结构、位置比例和速度/流畅度；教师能逐项覆核。避免把受地区字形/笔顺规范影响的标注当唯一真值。
- **标注条件：** 同一目标字符分别采集描红、临写、无提示书写，并记录提示级别；独立教师盲评、多评者一致性，保存争议/可接受变体。测延时无提示回忆和未练字符/相似部件迁移，不只评训练中同一轨迹。
- **采集信号：** 经明确告知与监护授权后，记录笔画点坐标、时间戳、笔落/抬笔、顺序、屏幕/画布尺寸、输入工具（手指/主动笔）、系统与采样特征；如果要以压力、倾斜或速度作判断，只有在设备可靠提供、跨设备校准后才使用。拒绝收集非必要生物特征或行为数据。
- **代表性与划分：** 覆盖年级/年龄、汉字熟悉度、简繁字形及地域/教学标准、运动能力、输入工具与设备；训练/验证/测试按孩子与字符隔离，另测跨设备和新字符泛化，避免同一个孩子/字同时泄漏进训练和测试集。
- **验证指标：** 与教师 rubric 比较每个标签的精确度/召回率、误判类型、置信度校准、跨年级/设备/输入方式误差；对低置信度结果 abstain（不判），提供“请老师看”入口。检查模型是否只靠模板提示、笔画顺序提示或画布位置给分。
- **学习效果而非识别分数：** 用预先规定的延后独立书写、纸笔样本与新情境迁移作为结果变量；比较有/无自动反馈条件下的学习增益和伤害，并经教师/家长/儿童试点复核。上线后仍将练习记录、自动识别建议和掌握状态分开，除非证据支持后续改变。

## 推荐 MVP

1. 先做仅支持少量经教师审核汉字的本地互动小课：示范动画 → 描红 → 看范字临写 → 隐去目标字形、只给读音/意义/情境线索的无提示尝试 → 显示对照与解释；每个阶段清楚标示线索水平。
2. 用仓库已有 SVG 与手势依赖实现画布，不加依赖、不下载全量第三方数据集。首批素材由内容负责人逐字绘制/审查，记录标准、来源、审核及许可。
3. 学习端只给过程提示与练习完成反馈，不自动报“正确率/掌握”。记录活动内的尝试阶段即可；不改变现有考试成绩、练习成绩、XP、长期复习安排。
4. 提供非绘画替代任务与清晰说明；书写能力目标可选择纸笔照片人工评分，使用现有私有附件与手动作业审核流程，而不将照片识别为轨迹判分。
5. 教师审核重点：字形标准/区域差异、目标笔顺、字体许可、儿童措辞与反馈、画布可操作性、替代路径和纸笔迁移。开展不同年龄与设备的可用性试点后，再决定是否需要轨迹持久化与评测研究。

画布也可服务数学演算、数轴或几何标注，以及科学观察图、结构示意图等开放表达；这些任务不应套用汉字轨迹相似度。每个学科须定义自己的 rubric（例如数学看步骤与表示是否合理，科学看图示是否对应观察），开放作品先采用教师人工反馈。
