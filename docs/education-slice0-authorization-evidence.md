## Findings checked against the requested cases

### Nonexistent resource vs. no access

Both responses are HTTP 404 with the same serialized `ApiResponse` body (`success=false`, `message="Study content not found."`, `data=null`, `errors=null`). The course-level learner query was changed to use the shared message; before that correction the missing-course message was `Course not found.`. Integration assertions compare the complete bodies for an existing private course vs. an unknown course, and an existing private objective vs. an unknown objective. CSV import denial is also compared with a nonexistent objective and returns no parser row errors.

Evidence: `EducationStudyItemLearnerQueries.cs:77-81,150-160`; `EducationStudyItemCommands.cs:34-38,91-97`; test `Missing_and_forbidden_learner_course_responses_are_identical_and_csv_errors_are_owner_only`.

### Withdrawal and assignment history

Every learner read calls `EducationAccess.IsActiveClassTeacherAsync` or `IsActiveClassStudentAsync` for the current classroom membership on that request. Those existing methods require an active, nondeleted classroom and, for students/teachers, an active nondeleted membership (`apps/api/src/MemoPal.Application/Features/Education/Relationships/EducationAccess.cs:9-18`). A withdrawn student is denied even if a classroom assignment exists. The old assignment path remains: a current active classroom member can still read a course linked to a classroom assignment after the explicit link is removed. Current authorization is classroom membership based; the existing path does not require that a student be an individual assignment recipient. No authorization helper semantics were changed.

Evidence: `Active_classroom_members_can_read_published_only_and_other_or_withdrawn_members_are_denied`; `Explicit_classroom_course_link_authorizes_active_members_and_preserves_assignment_access_after_unlink`.

### Moderation hiding and owner access

Course-author item listing still checks course ownership and course deletion, but not moderation-hidden state, so the owner can inspect author records after a report hides the course. Learner routes reject a hidden course before considering owner/public/classroom access. Evidence: `EducationStudyItemCommands.cs:34-38,51-56`; `EducationStudyItemLearnerQueries.cs:24,77-81,155-160`; test `Moderation_hidden_course_immediately_denies_published_item_reads`.

### Draft leakage and counts

The discovered defect was that the learner item handler included Draft when the caller owned the course. It now filters to `Status == Published` for every caller. The course objective count and classroom course summary also count only nondeleted Published items. Thus Draft content does not affect learner item lists, counts, summaries, or positions returned to learners. Author listing remains the only endpoint that returns Draft rows.

Evidence: `EducationStudyItemLearnerQueries.cs:86-88,161-164`; `EducationClassroomCourseCommands.cs:121-128`; tests `Owner_can_manage_items_and_public_learner_gets_safe_read_projection` and `Explicit_classroom_course_link_authorizes_active_members_and_preserves_assignment_access_after_unlink`.

### Import error visibility

CSV handler checks the course/objective owner relationship before parsing. JSON and batch import also enter `ImportObjectiveStudyItemsHandler`, which checks ownership before inspecting item rows. Unauthorized callers receive the same 404 as a nonexistent objective and cannot learn another course’s item count or row validation details.

Evidence: `EducationStudyItemCommands.cs:91-97,107-112`; test `Missing_and_forbidden_learner_course_responses_are_identical_and_csv_errors_are_owner_only` and the stranger cases in `Every_author_endpoint_denies_unrelated_users_and_anonymous_learning_reads_are_rejected`.

## Defects found and corrected

1. Owner identity caused Draft study items to be included through the learner read route. The learner query now returns Published only; author listing retains Draft access.
2. Missing course and unauthorized private course returned different 404 message bodies. Both now return the same `Study content not found.` response, with full-body equality assertions.

No change was required for CSV import ordering, course owner access after moderation hiding, active-membership revalidation, answer-key projection, or student DTO counts. No preexisting `EducationAccess` method was modified.

For each route, omitting `dryRun` or using `dryRun=false` preserves commit behavior. Commit requests rebuild the plan from current database state, so a preflight is advisory and stale results are not trusted. Current limits are 1000 input rows, 1 MiB raw import body, and the existing 100 study-item-per-objective cap. Preflight does not save entities, update timestamps/versions, or create practice, XP, or education-attempt records. The integration test snapshots the study rows and relevant write counts around preflight.

Stable import error codes emitted by the API: `InvalidEncoding`, `FileTooLarge`, `TooManyRows`, `ItemsRequired`, `ItemsLimitExceeded`, `RequiredField`, `DuplicateValue`, `DuplicateStableKey`, `PublishedItemConflict`, `InvalidPosition`, `InvalidKind`, `InvalidLanguage`, `InvalidGradeCode`, `InvalidMediaRef`, `InvalidCharacters`, `FieldTooLong`, `InvalidCsv`, `InvalidRow`, and `InvalidField`. Messages contain field/rule guidance only; clients should localize by code, not expose server internals.

**Authorization matrix:** The same owner checks apply with and without `dryRun`: course owner is allowed; unrelated user, another course owner, platform Admin without a course relationship, and a non-owner requesting a hidden course are denied; anonymous callers receive the existing authentication response. Existing import tests compare preflight/commit statuses and response bodies for the same caller and compare missing-objective vs forbidden-objective responses. Evidence: `EducationAuthoringController.cs:50-67`; `EducationStudyItemCommands.cs:91-136`; `EducationStudyItemImportPlanner.cs:14-79`; `EducationStudyItemEndpointsTests.cs` tests named above.
