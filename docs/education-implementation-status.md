1. Objective-question scoring and controlled mobile question inputs: single-choice, true-false, text/numeric fill-in. Implemented in authoring, server scoring, and the student assignment player using typed reusable question inputs.
2. Classroom membership and verified guardian relationships, server-side scope checks. Relationship APIs, owner/member scope, invitation acceptance and admin verification queue are implemented; mobile now lists non-expired classroom invitations on Home and the education assignment screen, accepts or declines them with confirmation, and refreshes the learner's assignment list. Home also presents guardian requests with the requester display name, explicit access scope, student confirmation or decline, and the waiting-for-admin state. Both parties can now review an active family link by the other party's display name and end that link after confirmation; the API returns the two names only to an authenticated link party, and existing server-side revoke authorization immediately gates report access. Mutations invalidate relationship/report caches. Product direction is that learner, student, teacher/author, and guardian are overlapping capabilities—not mutually exclusive account types. General public learning and practice do not require student membership; teacher publication does not grant access to learner identities or results. The Education portal login now routes ordinary accounts to the Education workspace and Admin accounts to platform administration unless a safe Education deep link was requested. Full role-based navigation/content discovery and device UX validation remain in progress.
3. Courses/objectives, versioned questions and assessments, assignments and recipient snapshots. Authoring and classroom assignment APIs plus teacher course/question/assignment screens are implemented. Teachers can preview the student-visible question form before saving/publishing; the preview receives an explicit safe projection that excludes correct answers, answer IDs, rubrics and objective IDs. Teachers can add an optional per-question explanation; it is only included in a student's attempt DTO after submission and result publication, and is hidden again when publication is revoked. Additive migrations include `20261018053712_EducationQuestionExplanations`; EF reports no pending model changes.
4. Student attempt start, answer saving, submission, deadline handling, server grading and publication. Start/resume, serialized versioned autosave, timed submission and server grading are implemented. Answer saves and private-attachment uploads share one serialized version queue so concurrent writes cannot race the attempt version; failed writes do not poison subsequent retries. Submitted scores remain null in student responses until the assignment owner publishes them; the result timestamp is included only while publication is active. Submitted student attempts, visible leaderboards and guardian reports refresh while open, and React Native refetches stale queries when returning to the foreground, so a correction/republication does not leave cached scores visible indefinitely.
5. Teacher authoring/assignment/gradebook workspace and student assignment screens using shared question components. Course/question editor, classroom assignment UI, student assignment player, teacher gradebook, explicit result publication and audited final-score correction are implemented. Teachers can authorize a targeted retake after the original result is published and fully graded; the reason is retained on a separate linked assignment, the original attempt/grade remain immutable, retakes cannot chain, and retake scores do not produce or expose a class ranking. Guardian users can assign their own published assessments to verified children from the reusable Family practice workspace, list those assignments, and reuse the same gradebook/publication flow. Manual student submission now uses the shared confirmation modal and warns that submitted answers cannot be changed; timeout submission and idempotent retry remain direct. Submitted students can optionally share a localized progress summary containing question count and formats only; the reusable share component never receives question text, answers, feedback, or score. Correction invalidates publication; the teacher/guardian must republish before students/guardians see the revised result.
6. Parent reports, course/objective evidence, classroom assessment rankings and correction flows. Verified-guardian child list and privacy-filtered assignment/results reports are implemented. Published family reports reuse the shared response-type performance calculator and show option-based and open-response results separately; unpublished, stale-version, or grade-corrected attempts do not expose per-question category breakdowns. Teacher/owner classroom objective progress uses published results, immutable assessment-version checks, distinct question/assessment/date thresholds, a 30-day evidence window, historical revalidation states, and excludes corrected attempts. Option-based and open-response results now have separate scores and evidence counts; only open-response evidence can advance mastery status, while option-only evidence receives an explicit non-mastery status. Students can view their own rank/score after publication; a teacher may enable a full classroom score table per assignment, and each student separately opts in to appear under an assignment-specific pseudonym. Publication persists a frozen rank snapshot; correction revokes the active publication, and republishing creates a new snapshot. Student reads expose no other account IDs or names; current membership and recipient authorization are checked on every request.
7. Additional question types (ordering, matching, multiple selection), accessible inputs and scoring. Multiple-select, ordering and matching are implemented end to end with reusable authoring/input components, typed answer contracts, server-side validation/scoring, save/restore, and unit/integration coverage. Ordering presents a teacher-authored starting order, requires a different full correct sequence, and offers accessible up/down controls rather than drag-only interaction. Matching uses independently displayed left/right lists, supports partial pairing and proportional partial credit, and never exposes the answer key to students. Shared student question inputs remount by attempt/question identity, clearing component-local interaction state (such as the active matching row or recorder UI) when changing question or attempt while keeping answer state in the parent.
8. Written-response questions with teacher rubrics and reusable manual-grading UI are implemented. Submitted work remains unscored until every written/photo/voice response is graded; publication is blocked while grading is pending, and scores/feedback remain private until publication. Teacher/verified guardian authorization, one-time grading and concurrent update conflicts are enforced. Photo responses upload validated JPEG/PNG/WebP; voice responses upload validated audio formats to private storage, replace prior attachments, bind files to the active attempt/question, and authorize each read for the student, current teacher or verified guardian. Voice is a manual-grading pilot only: no automatic transcription or pronunciation scoring. Mobile has reusable photo and recording inputs; recordings can be replayed after upload and replaced by recording again. A restored voice answer retrieves audio through the authenticated attachment endpoint; Web uses a temporary Blob URL and native platforms use a cache file removed when the input unmounts. Recording locks navigation/manual submission, and timeout waits for recording stop before submission; admin gradebook displays images/audio through authenticated attachment queries; private storage paths never enter client DTOs. Deployment uses a separate persistent host mount for private attachments and documents backup alongside the database and public uploads. ## Architecture constraints

- Existing MemorySet and self-reported PracticeAttempt retain their current purpose.
- Formal question DTOs sent to students never contain answer keys. Scoring runs server-side.
- Components receive typed values/callbacks; they do not perform networking or decide grades.
- Family/classroom permissions are relationship-scoped, not global Teacher/Admin access.
- Grade publication and mastery evidence use declared rules and immutable content versions. Classroom leaderboards use assignment-scoped frozen snapshots, teacher enablement, and per-student alias consent; these remain separate from the opt-in anonymous Community participation board and its independent point calculation.
- A teacher-authorized retake is a separately linked assignment. It preserves the original result, is never ranked against the original class assessment, and is excluded from objective mastery evidence so repeating the same assessment cannot inflate the evidence threshold.
- Identity handoff is copy-only: a student can copy their own account ID for a teacher/guardian to initiate a request; there is no public account lookup. Classroom member display names are returned only after server-side owner/active-teacher authorization, and an ID alone never grants access.
- Shared helpers/components must have concrete reuse across authoring, practice, assignments or reports; no speculative plugin framework.
- Every stage requires failure/ownership tests appropriate to its behavior and review before dependent work is dispatched.
