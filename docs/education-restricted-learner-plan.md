# Restricted Learner implementation plan

Date: 2026-10-26. Status: implemented; final check results are recorded below. Existing uncommitted Education work is preserved.

## Scope and entities

Add AccountMode (Standard / RestrictedLearner, database and CLR default Standard) to User; add AccountModeAudit with operator, subject, previous/new mode, reason, UTC timestamp and action. One separate additive migration, rollback to 20261025184343_AddEducationObjectiveDerivedMemorySets; rollback removes only the new account-mode column/audit table and therefore discards this feature's audit history. Do not apply production migrations. Organization/account provisioning is out of scope; later provisioning sets this server-owned field.

Admin-only PUT /admin/users/{userId}/account-mode sets mode with a reason and returns only a success boolean. Separate explicit POST /admin/users/{userId}/memory-sets/{memorySetId}/make-private may privatize one existing restricted account's set with an audit reason; no automatic bulk changes. Neither operation returns learner content. Existing non-private resources are excluded from Community at query time immediately; no existing content is deleted or silently migrated.

## New execution policy

Each action must have its own RestrictedLearner attribute: Allow / Conditional / Deny. Global authorization filter reads current persisted mode for every authenticated request (no claim/cache reliance), rejects missing classification and Deny with generic ApiResponse 403. Reflection tests require every concrete Controller action to have exactly one declared classification, including aliases. Existing role/owner/class/guardian authorization remains required. Standard user behavior is preserved.

Conditional resource handlers keep owner checks; a new additional education read policy returns only current active classroom access via course links OR assignments for RestrictedLearner, without editing EducationAccess or EducationStudyItemAccess function semantics. MemorySet create/update/visibility reject non-private input for restricted accounts. Public MemorySet query roots, counts/reactions/copies and weekly participants/ranking/rewards exclude restricted owners/users. Existing classroom leaderboard consent logic remains unchanged.

Uploads through MediaController and Auth.UploadAvatar create public URLs (Program.cs static file middleware); restricted learners cannot call them. AI generation sends material to external providers and is denied, although local Palace/Peg CRUD and practice remain available. Editorial collection/onboarding catalogs are denied pending a future institution-scoped content policy; no Community allowlist expansion. No public profile/friend/comment/chat controller exists in the current inventory. Static assets are not Controller actions: historical public URLs and anonymous sessions are a separate limitation, not revoked by this account policy.

## Tests and checks

Unit: default/policy decisions, all actions classified with safe defaults, adaptation matrix for every MemoryContentType x palace/number-peg. Integration: restricted/standard representative routes in every category, generic 403, author/private isolation, ownership denied, same token immediate toggle, admin audit and non-admin rejection, legacy public MemorySet hidden including known-ID copy/reactions, explicit audited privatization, weekly existing participant exclusion with standard snapshot unchanged, class-only bridge and withdrawal, no educational/XP side effects from mode or bridge reads.

Build and tests must not run simultaneously. Build first, then --no-build --no-restore; allow at least five minutes per command. Required: npm run check; solution build; API unit/integration serially and after completed build concurrently; EF pending-model check. PostgreSQL migration round-trip/concurrency only if MEMOPAL_CREDIT_TEST_CONNECTION exists, never expose its value.

## Risks and unresolved interfaces

No unresolved classification: the allowlist is deliberately limited to the requested learner workflows. Existing standard-author/Admin behavior is not redesigned. Requests already in flight at a mode change are not retroactively canceled; persisted mode is reread on the next request. No Organization, learner onboarding flow, private media migration, device/browser filtering or anonymous identity enforcement. Older copies already owned by other people and historical public URLs cannot be withdrawn by hiding a source row. PostgreSQL provider behavior remains unverified without the gated connection.

## Implemented conditional rules and evidence

- AccountMode comes from `apps/api/src/MemoPal.Domain/Entities/User.cs`; mapping is string-based, default Standard in `apps/api/src/MemoPal.Infrastructure/Persistence/AppDbContext.cs`. `apps/api/src/MemoPal.Application/Common/Mapping/MapsterRegistration.cs` exposes the persisted value in login/current-user DTOs; mobile/admin auth types are updated without UI changes. Neither registration nor login accepts a client-owned mode field.
- `apps/api/src/MemoPal.Api/Security/RestrictedLearnerFilter.cs` is globally registered in `Program.cs`, reads persisted mode per authenticated request and uses only method-local attributes. No account-mode JWT claim or server cache is used. Missing classification/unknown enum classification is denied for RestrictedLearner. New unclassified test-only action returns 403, while Standard reaches it. Conditions below still require existing resource authorization; they are not unconditional grants.
- MemorySet CRUD/folders/practice: existing owner-scoped handlers remain required. `AccountRestrictions.RequirePrivateAsync` is additionally called by CreateMemorySetCommand, UpdateMemorySetCommand and UpdateMemorySetVisibilityCommand. Private remains allowed; Public and Unlisted yield generic 403. Duplicate uses the existing Private duplicate request. Creating a non-private set was already forbidden for Standard users; that remains unchanged.
- Palace scenes: own custom scenes and the platform's published/unlocked templates use existing owner/template validation (`Features/PalaceScenes/Queries`). Number Peg definitions are platform configuration. External Palace/Number Peg story/image generation is denied; local/private creation and practice remain available. The queued image worker also filters restricted users and rechecks before provider invocation (`apps/api/src/MemoPal.Infrastructure/AI/AiImageWorker.cs`). Reserved jobs skipped by account filtering retain existing lease-expiry reconciliation; no silent data migration is performed.
- Education study/bridge: `apps/api/src/MemoPal.Application/Features/Education/StudyItems/EducationLearnerReadPolicy.cs` is an additional policy, used by learner queries and bridge LoadAsync. Restricted users must have an active classroom relation through assignments OR explicit course links, even if the course is discoverable publicly or owned by that restricted user. It does not change EducationAccess or EducationStudyItemAccess method bodies. It returns class-only assessment scope, so unrelated public assessment summaries cannot be obtained via a linked course. Withdrawal revokes source status/derive/sync; the learner keeps owner access to their personal copy. The global filter preflights these five restricted learner source routes before binding, so missing and unauthorized sources have identical generic 403 bodies; Standard users and other resource handlers retain their existing 404 behavior.
- Education attempts/attachments/my assignments: existing own attempt, published snapshot, release-time and attachment checks remain required. The global account policy additionally requires the restricted caller to be the attempt student (including attachment reads), so old teacher/guardian relationships cannot expand this surface; Standard teacher/guardian attachment rules remain unchanged. The creator-only GetAssignment and GetMyFamilyAssignments actions are denied, while my/assignments remains allowed. No teacher/guardian/author/Admin data access is added. Class leaderboard read/preference stays available under existing active membership, recipient and consent rules.
- Own stats, XP, milestones, companion, billing entitlement and credit balance/history remain scoped to the caller by their existing handlers. Practice can still earn personal XP/streak according to existing rules; formal Education scores/attempts do not enter practice/XP.

## Query exclusions and legacy content

`Features/Leaderboards/Queries/GetCurrentCommunityLeaderboardQuery.cs` filters opted-in users by current Standard mode before counting, scoring, rows, rank and projected credits. Stored participant rows are retained. `Features/Leaderboards/Commands/ProcessLeaderboardRewardsCommand.cs` excludes restricted users from new participant discovery, freeze calculations and pending award queries. Historical already-frozen results/previously granted credits are not rewritten; this is not a data migration. Standard opt-out participants retain their personal activity/final scores; only their original ranking opt-out remains in effect. A dedicated settlement regression test fixes this boundary. Legacy Public/Unlisted MemorySets keep their stored visibility while hidden; the owner can make a set Private, or a Standard Admin can explicitly privatize that one set, with an audit. Restoring Standard mode restores normal discoverability for still-public eligible sets; use explicit privatization if that is not intended.

## Existing education classroom leaderboard

Code-confirmed: `Features/Education/Assignments/Commands/PublishEducationAssignmentResultsCommand.cs` creates a snapshot for scored classroom submissions; all scored participants may contribute to internal ranks. ## Migration and rollback

New migration: `20261026004310_AddRestrictedLearnerAccountMode`, file `apps/api/src/MemoPal.Infrastructure/Persistence/Migrations/20261026004310_AddRestrictedLearnerAccountMode.cs`. Only Users.AccountMode varchar(32), non-null default Standard, and AccountModeAudits are added. Audit rows have Restrict FKs to operator/subject users and a subject/time index; time comes from the existing UTC audit hook. Reason validation is NFC, 1..300 code points without controls/format characters; storage ceiling is 600 to also accommodate UTF-16 pairs. There are no changes to existing content, participation, Education grades, PracticeAttempt or XP schemas.

Rollback (only on the intended isolated/deployment database after backup): `dotnet ef database update 20261025184343_AddEducationObjectiveDerivedMemorySets --project apps/api/src/MemoPal.Infrastructure --startup-project apps/api/src/MemoPal.Api`. It drops this feature's audit table and mode column, so preserve required audit records first. This command has NOT been executed against a real database here. The gated PostgreSQL test extends apply -> pre-Slice-0 rollback -> reapply assertions to the account mode/audit schema. Do not deploy older API code against this mode-enabled product without considering loss of the enforcement layer.
