## 1. 结论：建设通用学习能力，教育工作流作为其一

MemoPal 的学习与练习能力不应只服务于学生。任何玩家都可以学习公开内容、创建个人练习并追踪自己的进步；教育场景再叠加课程、班级、家庭关系、作业、测验和授权报告。记忆方法、内容库、练习引擎和分享能力尽量复用，课堂权限、正式评分和监护关系则作为明确的可选工作流，而非所有用户的前置条件。

正式成绩、家长跨账号查看和教师班级分析必须由授权关系、服务端评分与发布流程支撑。本文定义目标和交付顺序；实现状态以进度文档和当前代码为准，未完成的阶段仍按后续计划处理。

长期定位建议：帮助玩家“发现/创建内容 → 学习 → 练习 → 复习 → 分享进步”；教育工作流额外支持“布置 → 提交 → 批改/发布”。Number Peg 和 Memory Palace 是可选择的学习方式，选择题、数学练习或阅读理解不要求绑定记忆技巧。社区公开内容与老师发布的学习资源可共享发现/练习体验，但正式作业、答案和成绩不能因此公开。

## 3. 三种学习场景

| 场景 | 反馈与规则 | 成绩用途 |
|---|---|---|
| 自主练习 | 可看提示、答案、重复练习，保留自评模式 | 个人反馈、活跃度、复习建议；自评不进入考试成绩榜 |
| 家庭/课堂作业 | 有指定内容、接收者、截止日和尝试次数；提示政策由布置者设定 | 完成情况、第一次与最近一次结果、知识点证据 |
| 测验/考试 | 固定题目版本、时限、服务器判分、答案发布时机，支持人工批改 | 已发布的正式成绩与可选班级排名 |

首期适合家庭练习和课堂低风险测验。服务端判分能保护评分规则，但不能证明无人代答、查资料或使用其他设备；有监考和身份核验要求的高风险考试需独立评估，不能仅凭本模块宣称支持。

### 3.1 通用学习与教育工作流的边界

| 能力 | 面向对象 | 数据/权限原则 |
|---|---|---|
| 自主学习与练习 | 所有玩家，包括没有学生身份的成人、兴趣学习者和普通社区用户 | 默认个人空间；用户可从公开资料开始，也可创建自己的内容；进度属于本人，不需要加入班级 |
| 公开学习资料 | 教师、创作者及其他获准发布内容的用户；所有玩家可浏览和练习 | 发布者选择公开范围并声明授权；公开前校验内容与答案可公开；支持举报、下架、版本更新和来源标注；玩家可收藏课程，撤回后不再从收藏列表返回内容 |
| 家庭/课堂任务 | 已建立有效监护/班级关系的指定接收者 | 接收名单、截止时间、评分规则和结果可见范围由服务端强制；不因资料公开而公开作答或成绩 |
| 正式测验与报告 | 有权限的教师/组织者及被分配者 | 固定版本、标准答案保密、服务端评分；公开资料只可用于练习，不应被误认为保密考试题 |

公开资料可以是可复制/收藏的记忆集、练习组或课程资源；发布者可以允许“仅浏览”“复制到个人 Library”或“可用于自主练习”。教育课程公开与课程内测评公开练习是两次明确选择：只有老师/作者单独勾选“用于公开自主练习”的已发布客观题才进入公共目录；新建或发布的课堂/正式测评默认仍为私有。公开自主练习由服务器即时判题；可以保存玩家私有的最近练习索引（题目、最近作答时间和最近正误），以便本人回看和继续练习，但不得保存原始答案，不创建正式作业 attempt、不记录正式分数、不增加掌握证据或排行榜，也不向老师/家长报告。历史列表仅返回仍公开可发现的课程和题目；玩家本人账号隔离访问。玩家可主动分享近期练习数量摘要；分享不携带课程/题目名称、答案、正误、正确率或成绩，不自动发布到社区。教师发布的公开练习资料不自动授予用户教师身份，也不产生班级成绩或学生名单。若资料要用于课堂作业，应从已发布版本创建一个私有 assignment 快照，之后编辑公开原件不得改变已布置内容。公开测验仅作为练习测验；有标准答案的公开题可能被搜索或分享，不能保证测评公平性。正式测评须另行私有发布并按权限分配。

记忆素材与课程知识点之间建立可选引用：知识点可推荐一个公开或个人 `MemorySet`，玩家可将获准素材复制到自己的 Library 后用 Number Peg/Memory Palace 复习。引用不复制私人宫殿位置、联想文字或图片，也不让内容作者获得玩家的私有内容。学习引擎可以通用，教育汇报只能消费有授权且符合证据规则的测评数据；普通玩家不必拥有“学生”角色即可使用课程式内容或自我练习。

### 3.1.1 角色页面与公开资料发布

角色入口与页面分区统一见[第 5 节](#5-通用学习入口与角色化工作区)：角色不是互斥的全局账号类型；普通玩家无需学生身份即可学习，教师也可以同时作为普通学习者。导航按已有能力/关系显示，不给没有班级或教学权限的用户展示空工作区；具体页面不影响其个人记忆库和学习记录。

教师公开资料的发布流程必须把三类动作分开确认：①公开课程描述与学习内容；②每份测验是否可被所有登录玩家作为自主练习；③是否另行创建仅分配给指定班级/家庭的正式任务。第②项需在发布前明确告知“答案会用于即时判题，公开后不能作为保密考试”；公开练习者只留下本人的最小化练习历史。页面应标示作者、公开范围、适用题型和最近更新；作者可撤下内容，撤下后从目录、搜索、收藏和练习历史中消失。正式任务不能因复用同一课程或题库而意外继承公开状态。

### 3.2 教育内容与记忆工具的具体连接

两者不是互相替代的模块，而是“知识内容 × 记忆策略”的组合：课程/知识点定义要理解或掌握什么；题目练习用于理解、应用和检查；Memory Palace 与 Number Peg 是可选的编码、联想和提取练习工具。并非每个知识点都适合记忆法（例如复杂推理），因此关联必须可选，且老师不能强制所有玩家使用某种技巧。

建议的端到端体验：

1. 老师或内容作者编辑课程知识点时，可选关联一个当前可公开访问的记忆集；未关联时课程与练题照常工作。后续如果支持私有课程的个人素材推荐，必须另行按课程受众验证访问范围，不复用公开课程的公开 DTO。
2. 关联卡片展示标题、作者、记忆目标和技巧类型（宫殿/数字桩），并说明是否需要复制到个人 Library。它是推荐素材，不把记忆集的项目、联想、宫殿位置或图片内嵌进课程题目或作业快照。
3. 学习者打开推荐素材后，沿用现有社区详情、复制、Library 和记忆练习流程；需要编辑个人联想或宫殿位置时，先复制为自己的记忆集。成人自学者无需学生身份或加入班级。
4. 学习者可从知识点页返回“继续练习”，用同一知识点下的题目巩固；公开自主练习结果仅留在个人体验范围（若未来支持个人历史），不自动成为正式成绩或老师可见的掌握证据。
5. 教师作业/测验的知识点映射仍以题目所绑定的 objective 为准。可选记忆集只作为学习建议，不改变评分、完成状态、掌握度阈值或班级排行榜。

教师可以在课程知识点列表中随时更换或清除推荐，不需要重建知识点；如果原素材已经不可公开，工作台显示“不可用”，并允许教师清除旧引用或选择另一份当前公开素材。服务端仍逐次校验归属和素材可见性，不能因为历史引用而继续公开被撤下的内容。

权限与失效规则：仅允许关联本人拥有的素材，或社区 API 当前判定为可发现的公开记忆集；私有和 unlisted 素材不能作为面向全班/公众的链接。若公开集被作者下架、改为私有或被管理员隐藏，课程详情应立即隐藏推荐入口，并显示可恢复的“素材暂不可用”状态，不应在教育 DTO 或本地持久化一份绕过可见性检查的副本。关联保存稳定 ID，不复制内容；访问每次重新经过记忆集现有权限校验。课程公开与记忆集公开是两项独立授权，公开课程不会自动公开关联的记忆集，公开记忆集也不会自动公开课程或成绩。

首期只读推荐链接的选择范围是社区当前可发现的公开记忆集（选择公开记忆集 → 在课程知识点/课程详情呈现 → 跳转 Community 详情）；私有/未列出的个人素材关联仍是后续能力，需要单独定义课程受众授权。之后再评估“复制到 Library 后自动建立个人知识点快捷方式”、收藏和个人复习统计。不要把 MemorySet 的私密宫殿绑定写入课程、测评版本或公开分享卡片。

## 4. 角色、关系和访问范围

一个账号可以既是家长又是老师，角色随当前工作区/班级变化。保留平台 User/Admin 区分，新增范围明确的成员关系，不把单个 `User.Role` 改成互斥的 Parent/Teacher/Student 就视为完成授权。

| 使用者 | 可查看 | 可操作 | 边界 |
|---|---|---|---|
| 学生 | 自己的课程任务、提交、已发布成绩与反馈 | 学习、作答、交卷、复习、查看被允许的班级榜 | 不能读取其他学生答案或未发布标准答案 |
| 家长 | 已授权孩子的学习摘要、任务状态、已发布成绩、薄弱点与建议 | 切换孩子、布置家庭任务、设置提醒 | 不可修改老师的成绩；不默认读取孩子所有私人记忆内容 |
| 教师 | 所教班级成员、课程任务、答题结果、班级知识点统计 | 布置、批改、发布、补交/重考安排 | 不可浏览非任课班级或学生家庭/private 内容 |
| 班级管理者 | 自己管理的班级成员和权限 | 核验教师、加入/移除成员、处理绑定问题 | 不自动拥有全平台学生数据 |
| 平台运营 | 运维和支持所必需的范围 | 内容运营、权限支持 | 支持性访问有审计，教师不使用平台管理员账号 |

家长绑定流程：发起邀请 → 按儿童账号模式完成监护关系核验/确认 → 明确查看范围 → 生效。不能仅输入孩子邮箱或公开邀请码就读取成绩。支持一个家长多个孩子、一个孩子多个获准监护人、撤销和争议处理。儿童无需公开邮箱或真实姓名即可展示学习身份；实际账号创建方式在教育首期确定。

班级流程：经授权者建班 → 邀请教师/学生 → 待审核或由已验证名册确认 → 生效。邀请有期限且可撤销，加入码不能授予教师身份。教师退出/调班、学生退班和家长解绑后，服务端立即重新校验访问，清理受控缓存与导出链接；历史成绩保留按产品留存规则处理，不能因退班被误删。

身份交接采用最小暴露：学生端仅复制本人账号 ID 供老师/家长发起关联，不提供公开用户搜索；班级成员的显示名称只返回给通过服务端成员权限校验的班级所有者/教师。家长关联仍须学生确认和管理员核验，账号 ID 本身不是授权凭据。

孩子的学习空间和家长管理空间切换需要成人重新验证，不能在孩子会话里无验证切换成家长。每次数据访问检查关系与范围，不能只依赖长期 JWT 内的角色。

## 5. 通用学习入口与角色化工作区

产品采用“通用学习体验 + 按需工作区”，而不是登录后先选互斥身份。“教育”是后台与规划中的工作流称呼，不应让普通玩家觉得自己必须是学生；面向所有人的用户入口优先使用“学习 / Learn”，而“课堂管理”“家庭”等名称只用于相应的受限工作区。任何玩家（包括成人自学者、兴趣学习者和没有班级关系的人）都能发现公开资料、创建个人内容、选择题型练习、复习并分享安全的个人进度；只有加入班级、建立监护关系或获得教师发布权限后，才出现相应的受限工作区。一个账号可以同时是学习者、家长、教师和内容创作者；切换工作区不切换或覆盖个人 Library、记忆工具与自主练习历史。

这里要区分“内容创作者”和“教师”：创作者可创建、发布本人有权公开的资料，并查看该资料的聚合使用反馈；这不需要教师身份，也不开放班级、学生名单、作业成绩或正式测验工具。教师能力由有效的班级/组织关系或明确授予的教学权限产生；教师也可作为普通玩家学习，个人学习数据不会自动进入教师工作区。学生不是必须写入账号的固定角色：普通玩家始终可以自学；只有作为某项任务的接收者或有效班级成员时，才出现相应任务与班级视图。

| 角色/状态 | 主要页面入口 | 默认看见的内容 |
|---|---|---|
| 角色/状态 | 主要页面入口 | 默认看见的内容 |
|---|---|---|
| 普通玩家/自学者 | Today、Library、Practice、独立 Community Tab、Profile | 今日复习和个人目标；个人/收藏的记忆材料与课程；自主练习历史；公开社区内容与安全分享；不要求学生身份 |
| 内容创作者（可与任何学习者身份并存） | Learn 中的“我的内容”入口；必要时进入创作者工作台 | 草稿、本人发布/下架的内容、发布预览与聚合使用反馈；无班级时也能发布公开练习，不显示空的教师班级面板 |
| 任务接收者（学生或其他受邀学习者） | 通用入口上增加“我的任务”，不替换普通导航 | 仅本人被分配的家庭/课堂任务、截止与提交状态、获准发布的反馈和本人排名；不见其他成员答案或未发布成绩 |
| 家长/监护人 | Family 工作区，可在多个孩子间切换 | 每个获准孩子的任务和已发布摘要；与教师任务分开展示；不默认打开孩子的私人记忆内容 |
| 教师（可同时自学或创作公开内容） | Teacher 工作区；若无有效教学关系，不显示班级管理入口 | 有权限的班级、课程/题库、布置和批改；公开资料管理与班级教学分区呈现；教师身份不带来跨班级或私人数据访问权 |
| 平台管理员 | 受控 Admin 工作区 | 内容审核、账号/关系支持和审计；不与教师工作区混为一体 |

移动端保留 Community 独立 Tab；公开课程/练习资料可从 Community 的内容分类或搜索发现，教师的私有班级与成绩管理不放进 Community。Library 管“我拥有/收藏的学习材料”，Practice 管“我现在怎么练”，Community 管“发现、互动与分享”，Teacher/Family 工作区管“被授权的教学与家庭关系”。教师主要使用 Web 工作台编辑长内容和查看班级矩阵，移动端可提供任务检查、简易发布/批改等高频操作；所有学习者复用同一套练习组件，依任务策略显示不同的保存、计时、提交和反馈状态。页面按能力与关系显示入口，但每个 API 仍需再次验证资源归属、关系和操作权限。

页面逻辑原则：公共导航展示稳定的个人能力（学习、记忆库、社区、个人资料），工作区入口按当前账号实际拥有的关系/权限动态出现；没有班级的创作者仍能进入“我的内容”，没有家庭关系的用户不显示空的 Family 页面。首页优先呈现所有人都可执行的下一步（继续练习、今日复习、发现内容），有授权任务时再插入“我的任务”摘要。手机端优先用首页任务卡和按需入口，避免多个低频角色 Tab 挤占主导航；桌面端可用工作区侧栏承载 Teacher/Family/Admin 的管理页面。角色差异改变的是数据范围和工作区工具，不是练习引擎、个人进度归属或社区身份；同一用户切换“学习者 / 教师 / 家长”视图时，不应丢失当前上下文，且需明确标记当前工作区、所查看对象与退出/切换路径。

### 5.1 学习者：每天知道下一步做什么

普通玩家的 Today 侧重今日复习、个人目标和继续上次练习，不出现空的班级/学生面板。有关联任务的学习者额外看到“我的任务”：待开始、进行中、待交、已交待批改、已发布结果与待复习。Practice 同时包含自主记忆练习和课程题目练习；课程入口可从 Community 发现、Library 收藏或任务卡进入，来源不同不改变权限和成绩规则。

学习流程：打开课程任务 → 阅读内容/示例 → 做练习 → 保存答案 → 提交 → 查看允许公布的反馈 → 按薄弱知识点复习。练习时可提供“用记忆法巩固”，数学推理等内容仍保留常规题解练习，不强制转成记忆集。

### 5.2 家长：看到是否完成、哪里需要帮助

家长首页按孩子切换，显示：

- 本周应交 5 份、已交 3 份、逾期 1 份；数量来自分配任务，不用启动 App 次数代替。
- 已发布分数，例如数学单元测验 16/20；未批改标注“待批改”，未发布标注“待发布”。
- 知识点证据，例如“分数比较：最近两次测验 7/10 分；约分：证据不足”。
- 最近一次提交/回忆时间和观察到的学习活动；“未记录学习活动”不等于确定孩子没有线下学习。
- 建议动作，例如“复习 3 道约分题”；默认每周摘要，避免逐题推送制造压力。

点击摘要可查看对应课程/任务的允许详情，不默认开放其他学生成绩或孩子私有宫殿照片。家长布置的任务与老师任务分别标注来源。

### 5.3 教师：知道谁没交、班级哪里不会

教师以 Web 工作台为主要入口：班级 → 课程 → 作业/测验 → 学生提交和知识点矩阵。

- 名册区分未开始、已开始、已提交、逾期未交、补交、待批改、已发布、免交。
- 班级矩阵按学生 × 知识点展示证据、最近测评日期和需支持项目，缺数据不能显示为掌握率 0%。
- 题目分析展示作答人数、错误选项分布、得分率；未提交人数单列，不混入作答正确率分母。
- 可给选定学生补充练习、发布讲解、安排补测，原始提交和评分修订保留。
- 成绩导出仅包含当前授权班级与已选择字段，短期下载链接和操作记录可追踪。

建议复用 `apps/admin` 的 UI 技术和通用组件，教师业务使用独立权限与功能区域；是否独立应用部署等使用验证后决定，不为未来场景先拆服务。

## 6. 什么叫“有学习”“进度”“分数”“掌握”

必须分别展示这些概念，不能只给一个 XP 数字。

| 指标 | 首期定义 | 限制 |
|---|---|---|
| 有学习记录 | 服务端接受过作答保存、提交或 Recall | 页面打开不是完成证据；时长仅为估计 |
| 作业完成率 | 已提交必交任务数 / 到期或所选范围内已分配必交任务数 | 免交从分母剔除，补交标记保留 |
| 课程进度 | 完成的必修活动数 / 发布且分配的必修活动数 | 可读完但不代表理解；发布版本定义完成条件 |
| 正式得分 | 已发布的服务端/教师评分 / 对应满分 | 分开显示首次、最新与正式采用成绩 |
| 知识点表现 | 指定时间窗、指定测评证据内的得分率 | 不直接称为真实长期掌握概率 |
| 掌握状态 | 符合课程规则的多次独立测评证据 | 自评正确率、XP、次数不能单独证明掌握 |

首期掌握规则建议：每道题归属一个主要知识点；取最近 30 天内不同测评的首次正式作答，至少 2 个不同日期、5 道不同题后才标“证据较充分”。达到 80% 得分率可标“目前较稳固”，60%–79% 为“继续巩固”，低于 60% 为“需要帮助”。这些是待验证的教学配置，不是科学认证标准。题目难度不同必须注明，样本不足显示“证据不足”，过期显示“需要再验证”。

同一道题连续重做、自评记忆题、带提示练习不作为独立掌握证据；它们仍在练习进度中可见。首次作答与后续提升分开，老师可钻取每个状态所依赖的题目、时间、评分版本。学生做错后可用现有记忆复习或新练习巩固，再用新题检查迁移。

## 7. 题库、作业与测验生命周期

### 7.1 多种答题方式与优先级

产品方向：扩展当前以输入答案为主的体验，支持选择、排序、配对等方式，降低孩子的输入负担，同时保留主动回忆。记忆技巧与题型分开：Number Peg/Memory Palace 帮助记忆，题型负责收集作答；同一个知识点可以有多个题型版本。

| 答题方式 | 适用内容 | 交付优先级 |
|---|---|---|
| 单选 MCQ（文字/图片选项） | 词义、概念、常识、图片识别 | 题型首期，教育 E1 |
| 判断题 | 概念辨别、常见误区 | 题型首期，教育 E1 |
| 填空/输入答案（含数值） | 拼写、数字、无选项的主动回忆 | 保留并完善，教育 E1 |
| 排序题 | 事件、步骤、数字桩顺序记忆 | 题型第二期，教育 E2 后增量交付 |
| 配对题 | 单词与意思、图片与名称、概念与定义 | 题型第二期，教育 E2 后增量交付 |
| 多选题 | 多条件判断、多个正确结论 | 题型第二期，教育 E2 后增量交付 |
| 语音作答 | 低龄孩子、口头回忆、语言练习 | 基础试点已实现：私有录音上传、上传后及恢复后授权回听/可重录 + 教师 rubric 人工评分；不做自动转写/发音评分 |
| 简答（文字） | 阅读理解、数学解释、开放题 | 已有端到端基础：教师 rubric、提交后人工逐题评分、成绩发布；扩展型题组仍属 E4 |
| 拍照提交 | 数学过程、手写作答 | 基础版已实现：私有上传与人工批改；孤儿文件（文件无数据库元数据引用）每 6 小时扫描，超过 24 小时才清理；已记录答案/附件的留存期与删除策略仍待定 |

### 7.2 练习选择与固定测评

自主练习可由玩家选择已支持的方式，或按课程规则推荐；没有合格选项的内容不能直接自动变成选择题。家庭/课堂作业由布置者设定允许的方式，正式测验固定题型、题目版本、提示与评分规则，接收者不能切换成更容易的版本后继续参与同一成绩榜。

一个单词的练习路径示例：看图选词 → 单词与意思配对 → 看图输入单词 → 用老师指定题型独立测评。不同方式关联同一知识点，作为独立题目变体保存；该路径是可选教学安排，不要求所有内容都走完全部步骤，也不提前实现复杂的自动难度推荐。

每题先作答再提交，练习按规则显示正误、解析与重试；测验按公布策略延迟反馈。单选点选后明确高亮，提交前可修改；排序/配对除拖动外提供点击或移动按钮替代，支持大字体、屏幕阅读器和至少 44 pt 的触控目标。

### 7.3 题目质量与评分规则

- 单选首期建议 2–4 个选项且仅一个正确答案，判断题固定两个选项；干扰项应与知识点相关、表达清楚，不用明显无关项凑数量。AI 可以生成草稿，教师/内容作者审核题干、答案、干扰项和解析后才发布。
- 选项有稳定 ID，提交选项 ID 而不是 A/B/C 或画面位置。若启用随机排序，服务器为每次尝试保存顺序，恢复作答与批改时使用同一映射。含位置引用的题目不随机排列。
- 单选和判断按题目分值全对得分，否则零分；填空的大小写、空格、等价答案与数值误差由题目版本明确，不能用宽松文本匹配给数学过程题判分。
- 第二期多选默认选项集合完全匹配才得分；排序默认完整顺序正确才得分；配对默认每个正确配对等额计分。允许的等价顺序/配对须显式定义；若增加部分分或其他规则，在发布版本中固定并向学生解释，不临场改变。
- 当前语音试点只收集私有音频并由教师按 rubric 人工评分；不自动转写、不评价发音。后续若加入转写，须允许检查/修订转写文本和重录；发音评分需单独验证并明确告知，未验证的语音评分不能成为正式成绩。简答、作文和拍照解题采用人工 rubric 批改，AI 可建议，但不默认替老师发布最终分数。

### 7.4 学情与排名中的题型口径

结果记录题型、知识点、首次作答、提示/揭晓使用、重试次数与评分来源。报告分开显示“有选项的识别”和“无选项的主动回忆”，不能把 MCQ 正确率直接等同于输入答案的回忆率。

课堂目标进度将单选、多选、判断、排序、配对归为“选项式作答”，将填空、文字简答、拍照作答归为“开放作答”；两组分别展示分数、题量、测评数和日期数。掌握状态只依据开放作答证据计算；仅有选项式成绩时明确显示“仅有选项式证据”，不标为“目前较稳固”。此分类描述作答结构，不代表开放作答已经证明长期掌握。

第 6 节的掌握证据按能力目标和题型分组使用：选择题可以支持概念辨别证据，但不能单独证明拼写或无提示回忆。仅有识别题证据时注明“识别表现”，无主动回忆证据时明确显示缺口。混合试卷可按发布的分值计算总分，报告同时提供分题型表现；班级成绩榜只比较同一测评及评分条件，不把用户自由选择的不同练习方式混排。

### 7.5 多题型体验与复用边界

本次需求确认：答题不应只有自行输入；增加 MCQ 等交互方式，同时保留输入答案。题型规划和当前已经端到端支持的题型分别见本节表格及实现进度文档。

当前实现边界：已实现两类彼此隔离的自主复练。其一是作业复练库——学习者浏览本人已提交且成绩已发布的任务，按题型筛选；服务端再次验证本人、提交状态、成绩发布和不可变版本，不下发答案键、不保存练习答案、不改正式 attempt/成绩/掌握证据/排行榜。其二是社区公开学习资料——任意登录玩家可发现作者公开的课程和显式选为公开练习的已发布客观题，使用同一组可复用题目输入；学生端 DTO 不含答案键，服务端即时判题，检查后才返回解析，并仅给本人保存最近练习题目、最近作答时间和最近正误，不保存原始答案；玩家还可收藏公开课程，收藏/历史接口均只列出当前仍公开的资源，不进入正式测评、教师/家长报表或社区榜单。公开内容仍不是保密考试题。课程内容复制和跨设备偏好同步仍未实现。

产品理由：让孩子可以用更轻量、直观的方式开始练习，减少重复输入带来的摩擦；题型多样化也能让练习更有互动感。但不能因此把所有题目都改成选择题：选择题侧重识别，填空/输入侧重主动回忆，课程应按学习目标组合使用，并以独立测评检查是否能迁移。自主练习可以选择可用题型，作业和测验由教师/课程固定题型，保证成绩公平。Community 仍是独立 Tab；答题模式属于 Practice/课程任务流程，不在社区里另造答题入口。

- 练习入口展示授权内容实际支持的题型并记住用户的本地筛选偏好；所选题型没有可访问内容时清楚提示。内容不支持该方式时不生成未经审核的干扰选项。正式任务显示指定题型，不提供影响评分条件的自由切换。
- 共用题目卡片负责题干、题号、进度、提示状态和错误展示；单选、判断、填空等输入组件只接收题目、当前答案、禁用状态和变更回调。练习、作业和测验复用输入组件，分别控制反馈与提交政策。
- 区分未作答、已选择/输入、保存中、已保存、提交失败和已提交；选择一个选项不立即自动交卷。恢复后保留已确认的答案；重复点击提交不得重复评分或奖励。
- 结果页提供继续巩固、尝试无选项回忆和分享个人成果入口。分享是可选动作，只包含题型、完成量、学习天数等安全摘要，不包含题目答案；选择题成绩不包装为已经掌握主动回忆能力。
- 社区参与计分不因切换题型或重复同一学习事件额外发奖。不同题型的完成率、放弃率和后续独立回忆表现分别观察；更容易完成或点击更多，不直接视为学习效果更好。

首期验收应覆盖同一题目组件在复练与正式任务中正确使用不同反馈政策，以及空答案、非法选项、保存失败、恢复作答和重复提交。已交付复练范围的额外验收包括成绩未发布/非本人/非客观题拒绝，复练判定不改变正式 attempt、成绩或排名；不为尚无调用场景的题型提前建设插件框架。

### 7.6 内容与提交生命周期

内容流程：课程草稿 → 单元/知识点 → 题目草稿 → 试卷预览 → 发布不可变版本 → 布置给具体学生。修改已发布题目创建新版本，已开始的任务保留原题目、满分和评分规则。

任务状态与提交状态分别记录：

- 任务：草稿 → 已排期 → 开放 → 截止 → 归档，可取消。
- 学生尝试：未开始 → 进行中 → 已提交 → 待人工批改/已评分 → 已发布。
- 逾期、免交、缺交、补交为分配/提交属性；缺交不伪造为一张零分试卷。

测验流程：服务端验证班级身份、时间窗和尝试次数 → 创建 attempt，锁定题目版本、随机顺序和 `expiresAt` → 逐次保存答案 → 幂等交卷 → 自动评分 → 必要时教师批改 → 发布成绩/题解 → 生成允许的排名快照。

规则在发布时确定：可用提示、尝试上限、正式成绩取首次/最高/最后、是否允许补交、题解何时公开、是否参加成绩榜。课堂测验默认首次有效提交为正式成绩；练习允许重做，首试和最近一次均展示。个别补测经老师授权留下原因，不能悄悄覆盖原始分数。当前课堂补测通过独立关联作业交付：原结果须已发布且完成评分，由原任务教师为仍在班学生填写补测原因；补测保留独立提交/分数，不改写原作业，且不生成班级排行榜快照。

服务端控制截止和交卷。自动保存与最终提交分别显示；网络中断不显示“已提交”，重连后取服务器状态。定时测验到期按最后成功保存的答案封卷，后台重试只处理同一个 attempt；未保存答案按规则留空。无网络时允许恢复草稿，但首期不支持离线正式考试或按客户端时间补交。多人设备同时编辑通过版本号拒绝旧写入，已交卷不可继续改答。

若题目有错，教师发布评分更正版本，重算受影响成绩并重新发布；保留原评分、原因、操作者，重新生成排名与通知。申诉入口对应具体题目/提交，处理前显示状态，不能让学生自行改变正式答案。

## 8. 排行榜适配：三个用途，三个独立规则

| 榜单 | 比较对象 | 数据来源 | 可见范围 |
|---|---|---|---|
| 社区学习坚持榜 | 同一联赛组的参与用户 | 已定义的每日学习分 | 符合社区参与资格的用户 |
| 班级学习参与榜 | 同班学生的课堂任务参与 | 相同必交活动的完成天数/完成率 | 班内，可由老师启用 |
| 作业/测验成绩榜 | 同一测评版本与评分条件下的学生 | 已发布正式成绩 | 默认本人名次；班级展示另行启用 |

学生确实可以在已发布测评结果中查看自己在班级/某次测验的排名，并可在老师启用且学生同意时查看化名完整榜；只有有效班级成员可进入。家长在孩子报告中看该孩子获准显示的名次，不因此获得全班实名成绩表。当前 Community Tab 仅承载公开记忆集探索，通用社区 Leaderboard 尚未实现，也不作为班级成绩榜的入口。

成绩榜发布条件：同一任务比较组截止、评分完成且成绩已发布。未交/缺席/免交/待批改不按 0 分排最后；明确“已发布可排名人数 / 应参加人数”，有待批改时不发布最终名次。未交名单仅老师/对应家长可见。

同分并列，不用耗时做默认平分规则。例如 90、85、85、80 分显示 1、2、2、4。不同试卷、不同正式取分政策及不同评分尺度不直接排名；补测不同卷单独报告。提供延时等无障碍安排且题目和评分尺度相同的学生，不因用时不同被降权或排除。

默认向学生展示“我的成绩、我的名次、参评人数”，不展示公开落后名单；教师在布置课堂作业时可选择开启化名完整榜，默认关闭。每名学生还需单独主动同意将该次成绩列入完整榜；拒绝或撤回只影响完整榜展示，不影响作业、成绩册及个人名次。学生只能在成绩发布前更改该次选择，发布后锁定。完整榜仅返回系统生成的作业范围化名、并列名次和成绩，不返回账号 ID、姓名或缺交名单。成绩发布时以已提交且评分完成的同版本答卷生成不可变快照；更正会撤销当前发布，重新发布时生成新快照。面向儿童的班内排名授权与好友/公开社区同意分别处理，加入班级不代表同意公共曝光。

如果关闭成绩榜，仍提供本人前后进步与班级共同目标。公开成果分享不携带同学姓名、班级名册、答案或班级榜截图；经允许只分享自己的安全成果。考试得分不兑换社区学习分，正式作答如计入学习活跃天数只记一次完成事件。

## 9. 建议的数据边界

以下为需要时逐步建立的领域，不是现在一次性创建所有表的要求。

| 模块 | 主要实体 | 职责 |
|---|---|---|
| 家庭 | `GuardianStudentLink`、关系邀请 | 授权范围、核验、生效、撤销 |
| 课堂 | `Classroom`、`ClassMembership` | 班级所有权、教师/学生身份及历史 |
| 课程 | `Course`、`Unit`、`LearningObjective`、课程分配 | 结构、知识点、必修活动与发布版本 |
| 题库 | `QuestionRevision`、`AssessmentRevision` | 题目、答案、题解、分值、评分规则与试卷版本 |
| 布置 | `Assignment`、`AssignmentRecipient` | 任务版本、接收者快照、截止、免交与重考策略 |
| 作答 | `AssessmentAttempt`、`AssessmentResponse` | 原始答案、自动保存、提交、时间窗与幂等 |
| 评分 | `GradeRevision`、`GradePublication` | 判分、人工批改、更正、正式采用成绩与发布 |
| 学情 | 掌握证据与可重建报告投影 | 带规则版本的统计，追溯来源，不建立另一套可手改成绩 |
| 排名 | 任务范围的结果快照 | 正式成绩排序、人数、版本与可见性 |

保持现有 `MemorySet` 和 `PracticeAttempt` 的含义。新增 `AssessmentAttempt`，不把原来的自评历史转换为考试分数。课程活动可引用版本化记忆素材或试卷，不要求两种活动拥有相同评分字段；暂不设计通用插件引擎。

`QuestionRevision` 增加明确的题型与对应的版本化配置，`AssessmentResponse` 使用按题型区分的输入契约：单选 ID、判断值、填空文本；第二期再加入 ID 集合、排序 ID 列表和配对列表。客户端与后端保持类型对应，服务器检查选项归属、重复 ID 与题型不匹配；只为已交付题型编写渲染和评分逻辑，不先构建通用题型插件系统。

题库标准答案只存在受控服务端模型中；学生取题 DTO 与教师题库 DTO 分开，考试开始时不得下发答案。现有社区记忆集详情本来就包含答案，不能作为未揭晓考试的取题接口。公开题可以用于练习，不能承诺其作为保密考试题有效。

正式提交要保存学生答案以便批改和申诉，这与不记录答案到日志的要求不冲突：答案只存受权限控制的业务数据，日志、分析、社区、分享和通知均不包含原始答案。存储保留/删除与成绩留存分别制定，解绑不等于自动删除学业记录。

照片/语音答卷附件必须放在独立于公开静态媒体目录的私有存储中；上传和读取均须绑定有效 attempt/question，并在每次读取时验证学生本人、当前任课教师或已核验监护关系。校验文件大小与实际媒体格式，不向社区、日志或普通学生结果 DTO 返回私有存储路径。后台每 6 小时最多清理一次超过 24 小时、且完全没有数据库附件记录引用的合法文件名，用于回收上传后进程崩溃产生的孤儿文件；所有已登记（包括软删除）的附件都视为被引用，不会由此流程清理。发布后的附件留存期、用户删除策略以及答卷/成绩档案策略仍需分别制定，不能把孤儿回收当成产品留存规则。

## 10. API 与实现约束

API 草案按当前响应与 CQRS 模式实现，每个操作都校验实际关系，不能仅信任路由中的 studentId/classId：

- 家长：`GET /v1/family/children`、`GET /v1/family/children/{id}/summary`，关系邀请/核验/撤销用独立 mutation。
- 教师：`GET /v1/classrooms/{id}/progress`、`POST /v1/classrooms/{id}/assignments`，以及成员审批、评分与发布操作。
- 学生：`GET /v1/my/assignments`、`POST /v1/assignments/{id}/attempts`、`PUT /v1/assessment-attempts/{id}/responses`、`POST /v1/assessment-attempts/{id}/submit`。
- 结果：`GET /v1/assignments/{id}/my-result`、`GET /v1/assignments/{id}/leaderboard`；家长/教师使用受各自关系限制的结果接口。

当前教育 API 使用 `/v1/education` 前缀；学生班级成绩接口为 `GET /v1/education/assignments/{assignmentId}/leaderboard`，同意设置为 `PUT /v1/education/assignments/{assignmentId}/leaderboard-preference`。接口只向当前有效班级成员且本次任务接收者开放；完整榜需教师开启、学生分别选择加入，并且成绩已发布。采用并列竞赛排名（90、85、85、80 对应 1、2、2、4），未交者不按零分计入排名；学生端只收到化名行与自己的成绩行，不收到他人身份标识。发布时冻结排名快照，成绩更正撤销发布后旧快照不再可读，重新发布时产生新快照。

正式响应包括评分状态、版本、满分、发布时刻与数据口径；成绩未发布不泄漏分值、答案或间接可推断结果。学生输入原始作答和幂等标识，不接受 `score`、`isCorrect`、角色或审计字段作为评分事实。

数据库、现有 .NET 分层与 TanStack Query 足以作为起点。服务端处理身份、计时、判分、成绩与排名；客户端呈现和保存草稿。关系撤销、用户切换与成绩更正必须处理缓存失效。管理员、教师与家长的 query key 和数据访问范围隔离。

## 11. 交付顺序与现在要预留的边界

### 现在的社区计划应立即遵循

- Community 保持独立 Tab，榜单界面可明确展示“社区/我的班级”范围；尚无班级时不显示空入口。
- XP、学习分、正式成绩与掌握证据分开命名和计算。
- 公开分享只访问安全摘要；不能直接序列化将来的学生结果实体。
- 默认不公开儿童成绩，关系授权与班级授权由后端负责。
- 保留现有记忆模块，不提前创建空课程表或评分引擎。

### 教育 E1：家庭练习闭环

账号/监护关系、家庭任务、基础客观题与服务端判分、孩子结果、家长已发布成绩和完成情况。用一个家长、两个孩子验证相互隔离；支持正常撤销关系。上线前确定儿童账号与关系核验方式、目标年龄和发布市场；这些选择影响流程，不能以默认 User 角色替代。

题型首期包含单选 MCQ、判断、填空/数值输入，完成题目编写、预览、学生作答、保存、服务端判分与分题型结果的完整流程。

### 教育 E2：课堂作业闭环

班级、教师成员权限、课程/知识点、题库版本、任务接收者、自动保存与提交、教师成绩册、学生/家长报告。先用一门课程、一个单元、一次作业走通，不依赖社区好友功能。

课堂闭环稳定后增量交付排序、配对和多选，不阻塞使用首期题型的 E3 测验；文字简答、拍照提交和语音录音的人工批改闭环已作为增量实现。语音不阻塞课堂主流程。

### 教育 E3：测验、掌握分析与班级榜

限时尝试、评分发布、更正、补测、知识点证据、班级范围的成绩榜。试点连续两轮测评，验证同分、缺交、待批改、不同卷及退出班级的行为。

### 教育 E4：更丰富的教学

扩展语音转写/发音反馈、题目分析、题组/多步骤题、题库导入和更大规模的学校管理。文字简答、拍照提交和语音录音 + 人工 rubric 批改已作为 E2/E3 的增量基础实现：待批改成绩不可发布，教师逐题评分后才汇总，发布后学生才可见分数与反馈。AI 组题/评分建议需教师审核，不能默认代替教师发布最终分数；自动适应难度等能力在有足够数据后再验证。

教育 E1/E2 可以与社区建设并行规划，但公开社交不是教学依赖。若确定教育是下一阶段主要商业方向，应先交付家庭/课堂与可信评分，再扩大陌生人联赛、社交动态和复杂装扮奖励投入。

## 12. 验收场景

| 用户要求 | 具体证明方式 |
|---|---|
| 孩子能做习题与考试 | 客观题服务端判分，客户端篡改分数无效；提交重试不重复，超时答案按公布规则处理 |
| 多题型答题 | 单选、判断、填空可编写、作答、恢复与评分；随机选项恢复后 ID/顺序一致，非法选项和题型不匹配被拒绝 |
| 不同题型的学习反馈 | 报告区分识别与主动回忆；自主切换题型不改变正式测验，不混入同一成绩榜 |
| 后续题型交付 | 排序/配对有非拖动操作；多选、排序、配对按冻结规则判分；照片与语音进入私有存储并由教师人工批改；语音录制/上传失败可恢复，设备级流程仍待验证 |
| 家长能看进度分数 | 绑定后看对应孩子任务与已发布成绩；另一个孩子不可越权；解绑后缓存和接口均停止访问 |
| 老师看有没有学习 | 有分配名册，未开始/已开始/已交/免交分开；单纯打开页面不标已完成 |
| 老师看课程掌握 | 每个知识点状态可追溯到题目和评分版本；不足样本与重复练习不误判掌握 |
| 老师看分数并批改 | 原始作答、自动/人工评分与发布分离；更正有版本，家长和学生看到一致的新结果 |
| 学生看排名 | 同班同测评的已发布正式成绩排序；同分并列、待批改不作零分、不同卷不混榜 |
| 适配现有 MemoPal | 自主记忆、复习和社区仍正常，历史自评不转换为考试成绩 |

上述验收需结合领域/集成/客户端权限测试与设备上的交卷恢复检查。当前已有实现范围、测试结果和仍未交付项以[教育模块实现状态](education-implementation-status.md)为准；真实 PostgreSQL 迁移验证与 iOS/Android 设备流程仍待验证，不应据此宣称整个教育模块已经完成。
